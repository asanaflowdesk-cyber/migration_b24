# Возврат провальных лидов в «Новые»

Разовый безопасный процесс для исправления ошибочно переведённых лидов.

Критерии отбора:

- лид **сейчас** находится в провальной стадии `JUNK`;
- на текущую стадию его перевёл выбранный пользователь (`MOVED_BY_ID`);
- переход в текущую стадию выполнен за последние N дней (`MOVED_TIME`, по умолчанию 7 дней).

Это важно: процесс не использует `DATE_MODIFY`/`MODIFY_BY_ID`, потому что последующее редактирование карточки не должно менять факт того, кто именно перевёл лид в провал.

При переносе меняется только стадия на `NEW`; текущий `ASSIGNED_BY_ID` фиксируется перед изменением и передаётся обратно тем же значением. После запуска выполняется повторная проверка: если робот стадии успел изменить ответственного, исходный ответственный восстанавливается.

## GitHub Actions

Workflow: `32 | Лиды — вернуть мои провальные в Новые`.

Сначала запускайте `dry_run`. Для `apply` требуется подтверждение `REOPEN_FAILED_LEADS`.

`moved_by_user_id` можно оставить пустым: тогда используется `BITRIX_REOPEN_MOVED_BY_ID`, а если переменная не задана — пользователь, которому принадлежит `TARGET_BITRIX_WEBHOOK_URL` (`user.current`).
