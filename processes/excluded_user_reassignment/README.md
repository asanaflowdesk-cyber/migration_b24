# Перенос пакетов исключённых пользователей

Workflow: `33 | Исключённые пользователи — перенос пакетов`.

Процесс решает только задачу ответственных. Стадии лидов не меняются.

Правила:

1. Исходные лиды — лиды, у которых текущий `ASSIGNED_BY_ID` входит в `excluded_user_ids`.
2. При наличии учредителя пакет объединяется по ФИО учредителя и связанным компаниям.
3. Если учредителя нет, `компания + лиды` остаются полноценным сокращённым пакетом. Если нет компании, отдельный лид считается минимальным пакетом.
4. Лиды пользователей вне `excluded_user_ids` никогда не переназначаются. Они используются только как контекст пакета.
5. Если пакет уже закреплён за одним действующим владельцем вне списка исключённых, остатки исключённых сущностей доводятся к этому владельцу. Такой пакет не отправляется на новую балансировку.
6. Если пакет уже частично находится на `72` или `73`, остаток продолжает переноситься на того же РОПа.
7. Если действующего владельца нет, пакет целиком назначается на `72` или `73`; балансировка выполняется по количеству исходных лидов.
8. Если пакет связан с Талдыкорганом через подразделение исходных/текущих владельцев, пакет целиком пропускается.
9. Пакет, содержащий защищённый лид `401`, автоматически не меняется.
10. Меняется только `ASSIGNED_BY_ID` у исходных лидов и связанных карточек компании/учредителя. `STATUS_ID` не меняется.
11. После `apply` CRM перечитывается. Расхождения один раз повторяются в этом же workflow, после чего выполняется финальная проверка.
12. Формируется один artifact: `excluded_user_reassignment.csv`.

`dry_run` ничего не записывает. Для `apply` требуется подтверждение `REASSIGN_EXCLUDED_USERS`.
