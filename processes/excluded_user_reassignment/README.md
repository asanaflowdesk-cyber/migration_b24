# Перенос пакетов исключённых пользователей

Workflow: `33 | Исключённые пользователи — перенос пакетов`.

Процесс решает только задачу ответственных. Стадии лидов не меняются.

Правила:

1. Исходные лиды — лиды, у которых текущий `ASSIGNED_BY_ID` входит в `excluded_user_ids`.
2. При наличии учредителя пакет объединяется по ФИО учредителя и связанным компаниям.
3. Если учредителя нет, `компания + лиды` остаются полноценным сокращённым пакетом. Если нет компании, отдельный лид считается минимальным пакетом.
4. Лиды пользователей вне `excluded_user_ids` не переназначаются. Они используются только как контекст связей пакета.
5. Пакет, связанный с менеджером Талдыкоргана `16`, `18` или `38`, не меняется целиком.
6. Все остальные пакеты независимо от текущих владельцев компании/контакта заново распределяются целиком между РОП `72` и `73`.
7. Балансировка выполняется по количеству исходных лидов, пакет между РОПами не дробится.
8. Пакет, содержащий защищённый лид `401`, автоматически не меняется.
9. Меняется только `ASSIGNED_BY_ID` у исходных лидов и связанных карточек компании/учредителя. `STATUS_ID` не меняется.
10. После `apply` CRM перечитывается. Расхождения один раз повторяются в этом же workflow, после чего выполняется финальная проверка.
11. Формируется один artifact: `excluded_user_reassignment.csv`.

`dry_run` ничего не записывает. Для `apply` требуется подтверждение `REASSIGN_EXCLUDED_USERS`.

## Актуальное правило защиты 16/18/38

Решение принимается по **всем лидам, связанным с пакетом через компанию или контакт**.
Владельцы самой компании и контакта в голосовании не участвуют.

- если лидов **не на 16/18/38 больше**, чем лидов на 16/18/38 — пакет распределяется между РОП 72/73;
- если лидов на 16/18/38 больше либо количество равно — пакет не трогаем;
- лиды действующих менеджеров вне исключённого списка используются для определения большинства, но сами не переназначаются потоком 33.
