# Переназначение ответственных исключённых пользователей

Workflow: `33 | Исключённые пользователи — перенос ответственных`.

Правила:

1. Исходные лиды — лиды, чей текущий `ASSIGNED_BY_ID` входит в `excluded_user_ids`. Стадия лида не участвует в отборе и не изменяется.
2. Лиды группируются в неделимые пакеты. При наличии учредителя пакет строится по связанному учредителю/компаниям.
3. Если учредителя нет, но есть компания, формируется сокращённый пакет `компания + лиды этой компании`. Если нет и компании, лид остаётся минимальным пакетом из одного лида.
4. Единственная причина пропуска допустимого исходного пакета — связь с Талдыкорганом. Целевые РОП 72/73 при проверке филиала игнорируются: если они уже появились в пакете из-за предыдущего частичного переноса, это не превращает пакет в «Талдыкорган».
5. Чужие лиды сотрудников вне `excluded_user_ids` не переназначаются. Связанные компания и контакт допустимого пакета переходят вместе с пакетом.
6. Если пакет уже частично перенесён и внутри него есть ровно один целевой РОП 72 или 73, остаток пакета продолжает переноситься к этому же РОПу. Такой пакет не балансируется заново. Если один пакет уже расколот одновременно между 72 и 73, процесс останавливается с ошибкой вместо дальнейшего дробления.
7. Только полностью новые пакеты балансируются между 72 и 73 по количеству лидов. Пакет не делится.
8. `apply` изменяет только `ASSIGNED_BY_ID`. `STATUS_ID` и другие поля лида этот workflow не трогает.
9. После записи выполняется повторное чтение CRM и строгая проверка владельца каждой сущности. В логе показывается прогресс `X/Y` и итог отдельно по лидам, компаниям и контактам.
10. Формируется один artifact: `excluded_user_reassignment.csv`.

`dry_run` только строит план. `apply` разрешён после подтверждения `REASSIGN_EXCLUDED_USERS`.
