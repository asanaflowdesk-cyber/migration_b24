# Переназначение карточек исключённых пользователей

Workflow: `33 | Исключённые пользователи — переназначить все лиды`.

При ручном запуске в поле `excluded_user_ids` вводятся Bitrix24 ID через запятую,
например `17, 42, 86`.

Правила:

1. Исходными считаются все лиды указанных пользователей без фильтра по стадии.
2. Учредитель определяется по контакту руководителя. Все его компании, контакты
   руководителя и все связанные лиды образуют один пакет.
3. Каждый лид пакета получает нового ответственного и `STATUS_ID = NEW`, включая
   ранее успешные, провальные и иные закрытые лиды.
4. Все компании и контакты руководителя пакета получают того же ответственного.
5. Приоритет назначения: `Company_fix` → уже действующий ответственный учредителя
   из `user_list` → Астана/DepartmentID 46 → подразделение исключённого сотрудника
   → общий пул `user_list`.
6. Для нового учредителя выбирается наименее загруженный менеджер; при равенстве
   выбор стабилен между `dry_run` и `apply`. Один обычный менеджер получает не
   более одного нового учредителя за запуск, затем используется РОП.
7. Если учредителя нельзя определить, пакет ограничивается одной компанией; лид
   без компании и руководителя переносится отдельно и явно помечается в отчёте.

`dry_run` ничего не меняет и формирует CSV с прежними/новыми ответственными и
стадиями. `apply` разрешён только после ввода `REASSIGN_EXCLUDED_USERS`.
После записи выполняются две контрольные сверки с паузами для роботов Bitrix24;
если робот снова изменил стадию или ответственного, workflow завершается ошибкой.
