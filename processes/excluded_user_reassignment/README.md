# Переназначение карточек исключённых пользователей

Workflow: `33 | Исключённые пользователи — переназначить все лиды`.

При ручном запуске в поле `excluded_user_ids` вводятся Bitrix24 ID через запятую,
например `17, 42, 86`.

Правила:

1. Исходными считаются все лиды указанных пользователей без фильтра по стадии.
2. Учредитель определяется прежде всего по `CONTACT_ID`, прямо указанному в лиде.
   Маркеры должности и служебного комментария используются дополнительно, но их
   отсутствие больше не скрывает реально привязанного учредителя. Лиды указанных
   исключённых пользователей группируются в пакеты по учредителю.
   Если у компании несколько учредителей, их группы объединяются: вся связанная
   цепочка выбранных лидов назначается одному РОПу.
3. Жёсткая граница охвата — текущий `ASSIGNED_BY_ID`. Переназначаются только лиды,
   у которых текущий ответственный прямо указан в `excluded_user_ids`. Лиды любых
   других сотрудников не изменяются, даже если у них тот же учредитель, контакт
   или компания.
4. Каждый выбранный лид пакета получает нового ответственного и `STATUS_ID = NEW`, включая
   ранее успешные, провальные и иные закрытые лиды.
5. Компании и контакты пакета получают того же РОПа только тогда, когда их текущий
   ответственный также входит в `excluded_user_ids`. Карточки других сотрудников
   остаются у них для ручной обработки.
6. Получатели зафиксированы напрямую: РОП `72` отдела продаж №2
   (`DepartmentID = 65`) и РОП `73` отдела продаж №1 (`DepartmentID = 66`).
   `user_list`, `Company_fix`, прежний филиал и прежнее закрепление в этом
   workflow не участвуют.
7. Пакеты сортируются от большего количества выбранных лидов к меньшему. Каждый следующий
   целиком назначается РОПу, которому в текущем запуске уже запланировано меньше
   лидов. Это даёт максимально близкое к равному распределение без разделения
   одного учредителя между двумя РОПами.
8. Для автоматического переназначения обязательны существующая компания и
   определённый учредитель. Если `CONTACT_ID` отсутствует, контакт не найден или
   у него нет фамилии/имени, лид пропускается без изменений и записывается в
   `excluded_user_reassignment_skipped.csv` для ручного назначения. Его компания
   не включается в пакет только на основании этого лида. Отсутствующий или
   удалённый `COMPANY_ID` обрабатывается так же: карточка пропускается, но не
   блокирует обработку остальных пакетов.

`dry_run` ничего не меняет и формирует расширенный CSV. На каждой строке доступны
исходные исключённые ID, состав пакета, ФИО и ID учредителей, компании, БИН,
прямая связка лида с компанией и контактом, прежние/новые ответственные с ФИО,
а также прежняя/новая стадия с названием. `apply` разрешён только после ввода
`REASSIGN_EXCLUDED_USERS`.
После записи выполняются две контрольные сверки с паузами для роботов Bitrix24;
если робот снова изменил стадию или ответственного, workflow завершается ошибкой.
