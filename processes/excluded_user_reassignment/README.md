# Перенос пакетов исключённых пользователей

Workflow: `33 | Исключённые пользователи — перенос пакетов`.

Процесс меняет только ответственных. Стадии лидов не меняются.

Правила:

1. Исходные лиды — лиды, у которых текущий `ASSIGNED_BY_ID` входит в `excluded_user_ids`.
2. При наличии учредителя пакет объединяется по ФИО учредителя и связанным компаниям.
3. Если учредителя нет, `компания + лиды` остаются полноценным сокращённым пакетом. Если нет компании, отдельный лид считается минимальным пакетом.
4. Лиды пользователей вне `excluded_user_ids` не переназначаются. Они используются как контекст пакета и голоса при выборе направления.
5. По всем связанным лидам считается две группы: `16/18/38` и все остальные.
6. Если лидов не на `16/18/38` строго больше — пакет идёт в равномерное распределение между РОП `72` и `73`.
7. Если группа `16/18/38` больше либо равна остальным — пакет больше не зависает: остатки исходных лидов, компания и контакт переходят тому из `16/18/38`, у кого больше связанных лидов.
8. Если внутри `16/18/38` точная ничья по максимальному числу лидов, используется меньший ID менеджера как технический tie-break, чтобы пакет не оставался нерешённым.
9. Лиды действующих менеджеров вне исключённого списка никогда не переписываются потоком 33.
10. Пакет, содержащий защищённый лид `401`, автоматически не меняется.
11. Меняется только `ASSIGNED_BY_ID`; `STATUS_ID` не меняется.
12. После `apply` CRM перечитывается. Расхождения один раз повторяются в этом же workflow, затем выполняется финальная проверка.
13. Формируется один artifact: `excluded_user_reassignment.csv`.

`dry_run` ничего не записывает. Для `apply` требуется подтверждение `REASSIGN_EXCLUDED_USERS`.
