# Конфигурация миграции

## migration.json

Содержит:

- соответствия стадий облака стадиям лидов и сделок коробки;
- правило `LOSE → JUNK`;
- исключение четырех исходных лидов;
- поле страхового продукта в лидах `UF_CRM_1785917145255`;
- поле страхового продукта в сделках `UF_CRM_6A73073A5405E`;
- соответствия заполненных пользовательских полей;
- папку и максимальный размер файлов.

Изменять коды стадий и полей можно только после проверки потоком 10.

## users.csv

Ручные соответствия используются раньше автоматического поиска по email и ФИО.

```csv
source_user_id,target_user_id,comment
1,25,пример ручного соответствия
```

Не нужно добавлять строки для пользователей, которые однозначно находятся автоматически.

## Контекстное назначение пользователей

В `user_assignment.context_overrides` закреплены специальные правила:

- исходный пользователь `36` (`Sacheva Alena`): CRM-карточки и CRM-дела → пользователь коробки `21`, задачи и их участники → пользователь коробки `4`;
- исходный пользователь `96` (`Тестовый Сотрудник`): CRM-карточки и CRM-дела → пользователь коробки `21`, задачи и их участники → пользователь коробки `4`.

В `skip_tasks_if_participant_source_user_ids` указаны `10` и `28`. Любая задача, где Соболева Екатерина или Нуртазина Асель указана постановщиком, исполнителем, соисполнителем либо наблюдателем, полностью исключается из миграции. В текущем дампе исключаются 8 задач, поэтому ожидаемый итог — 589 задач.

Пользователи, которые не участвуют ни в одном импортируемом объекте, отображаются в отчёте как `SKIP` и не блокируют поток 11.
