# e-Qazyna — синхронизация статусов заявок с лидами Bitrix24

Процесс не создаёт новые лиды. Он берёт уже существующие e-Qazyna лиды в коробочном Bitrix24, извлекает номер заявки и выполняет точный поиск в публичном реестре e-Qazyna через `flDocNum`.

Правила изменения стадии:

- `Отклонено` → `Провал`;
- `Отозвано` → `Провал`;
- `Аннулировано` → `Провал`;
- `Выдана лицензия` → `Потенциальные сделки`;
- остальные статусы e-Qazyna не меняют стадию лида.

ID стадий не зашиты в код. Перед запуском процесс читает справочник стадий лидов Bitrix24 и находит нужные стадии по названию. Для потенциальной стадии также поддерживается вариант названия `Потенциальная сделка`. Если нужная стадия не найдена однозначно, процесс останавливается до изменений.

Номер заявки определяется из `ORIGIN_ID`; для старых карточек также поддерживаются старый составной маркер, заголовок и комментарий. Если в одной старой карточке обнаружено несколько разных номеров заявок, она не изменяется автоматически и попадает в отчёт как неоднозначная.

Поиск в e-Qazyna выполняется без фильтра по статусу, поэтому текущий статус заявки читается независимо от того, каким он стал. Сверка делается только по точному номеру документа.

Workflow: `33 | e-Qazyna — синхронизация статусов заявок`.

По умолчанию используется `dry_run`. Для записи требуется `mode=apply` и подтверждение `SYNC_EQAZYNA_STATUSES`.

Artifacts:

- `eqazyna_status_sync_summary.json`;
- `eqazyna_status_sync_results.json`;
- `eqazyna_status_sync_results.csv`;
- `eqazyna_status_sync_journal.txt`.
