# e-Qazyna — синхронизация статусов заявок с лидами Bitrix24

Процесс не создаёт новые лиды. Он проверяет уже существующие e-Qazyna лиды в коробочном Bitrix24 и для каждого лида сверяет текущий статус ровно одной заявки в публичном реестре e-Qazyna.

## Ключевое правило идентификации

**Один лид = одна заявка.**

Номер заявки берётся **только из названия лида (`TITLE`)**. Всё, что находится после символов `№ `, считается номером заявки.

Пример:

`ТОО Конор Н.А. e-Qazyna № 49667-NEA` → номер заявки `49667-NEA`.

`ORIGIN_ID`, комментарии и другие поля для определения номера заявки не используются. Если в названии нет `№ ` или после него нет значения, карточка не изменяется и попадает в журнал.

## Правила синхронизации

| Статус в e-Qazyna | Стадия лида Bitrix24 | `UF_CRM_1785508658316` |
| --- | --- | --- |
| `Аннулировано` | `Провал` | `66` — `Заявка аннулирована на сайте` |
| `Отозвано` | `Провал` | `67` — `Заявка отменена на сайте` |
| `Отклонено` | `Провал` | `68` — `Заявка отклонена на сайте` |
| `Выдана лицензия` | `Потенциальные сделки` | `69` — `По заявке уже выдана лицензия` |

Остальные статусы e-Qazyna (`Принято`, `Отправлено на рассмотрение`, `Завершено` и т. п.) не меняют карточку.

При срабатывании правила процесс синхронизирует **оба значения одновременно**: стадию лида и поле причины. Если стадия уже правильная, но причина отсутствует/неправильная, причина всё равно исправляется. Если и стадия, и причина уже совпадают — запись не выполняется.

ID стадий не зашиты в код. Перед работой процесс читает справочник стадий лидов Bitrix24 и находит `Провал` и `Потенциальные сделки` по названию. Для потенциальной стадии поддерживается также название `Потенциальная сделка`.

Поиск в e-Qazyna выполняется через `flDocNum` и после получения страницы дополнительно проверяется точное совпадение номера заявки. Фильтр по статусу намеренно не используется: процесс должен увидеть заявку независимо от того, в какой статус она перешла.

Workflow: `33 | e-Qazyna — синхронизация статусов заявок`.

По умолчанию используется `dry_run`. Для записи требуется `mode=apply` и подтверждение `SYNC_EQAZYNA_STATUSES`.

Artifacts:

- `eqazyna_status_sync_summary.json`;
- `eqazyna_status_sync_results.json`;
- `eqazyna_status_sync_results.csv`;
- `eqazyna_status_sync_journal.txt`.
