# Пакет учредителя ГПО недропользователя

Источник ответственного — контакт, связанный с лидом через `CONTACT_ID`.
Остальные контакты, компании и все их лиды получают его текущий
`ASSIGNED_BY_ID`. Лиды без компании, связанные с контактами пакета, тоже
включаются. Стадии и статусы не меняются.

## Связи и источник

Контакты распознаются по «руководитель», «учредитель», «директор» в должности
либо метке `EQAZYNA_DIRECTOR` в комментариях без учёта регистра. ФИО
нормализуется; разные отчества и противоречащие друг другу связи компаний
не объединяются автоматически. Компания включается по связи с контактом,
связи через лид или совпадению ФИО с `RQ_DIRECTOR` реквизита.

Дата изменения карточки не определяет источник. Дубль без связи с лидом
не может вернуть пакет на РОПа, если в пакете есть связанный контакт.

После успешного события ID источника сохраняется в `authority_sources.json`
вне runtime и остаётся после перезапуска. Без сохранённого источника связанные
с лидами контакты должны иметь одного ответственного. Разные ответственные
означают конфликт. Если сохранённый источник больше не связан с лидом, пакет
пропускается до исправления связи или нового корректного события.

## Worker и восстановление

`31A | Founder package worker control` управляет постоянным worker на Windows.
События хранятся в Google Apps Script очереди; Action не запускается на каждое
событие. Worker сначала освобождает очередь, затем сверяет остатки в CRM при
старте и раз в `OWNER_SYNC_RECOVERY_SECONDS` (по умолчанию 300 секунд).
Это исправляет пакеты при потерянном событии или поздней записи другого процесса.

Ответственный источника перечитывается перед записью и после неё. Результат
записи проверяется чтением. Смена источника вызывает повторную сверку; ошибка
оставляет пакет `PARTIAL`, который повторяется в следующем проходе. Совпадающие
карточки не обновляются. Последний результат: `output/recovery.json`.

Push изменений worker в `main` запускает тесты, перезапуск и ожидание свежего
отчёта сверки. В логе — сводка и ID источников изменённых пакетов.
Ручные команды: `start`, `stop`, `restart`, `status`.
Workflow 31 выполняет ручную сверку по той же логике, по умолчанию `dry_run`.
Отчёт: `company_lead_owner_reconcile.xlsx`.

## Внешние обработчики

Код обработчика: `integrations/bitrix_owner_sync_webhook/`.
Код очереди: `integrations/bitrix_owner_sync_queue/Code.gs`.
Кэш ответственного обновляется после сохранения задания, чтобы сбой записи
не превращал повтор события в `owner_unchanged`.

Apps Script требует отдельной публикации новой версии web app; push в GitHub
её не публикует. Сверка worker восстанавливает остатки и со старой очередью.
