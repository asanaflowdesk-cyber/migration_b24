# Сверка ответственных: руководитель компании → компания → лиды

Workflow: `31 | Компании — ответственный по руководителю компании`.

Источник назначения — `ASSIGNED_BY_ID` контакта руководителя, выбранного **в контексте этой же компании**. Совпадение ФИО по всему порталу не является идентификатором человека и не используется для переноса ответственного между разными компаниями.

Правило:

1. Загружаются компании, связанные лиды и контакты руководителей (`POST` содержит `Руководитель` либо присутствует marker `EQAZYNA_DIRECTOR`).
2. Для каждой компании сначала выбирается director contact, у которого `COMPANY_ID` равен ID этой компании.
3. Если прямой контакт компании отсутствует, допускается fallback только на director contact, который реально указан `CONTACT_ID` у лида этой же компании.
4. При нескольких кандидатах выбор детерминирован: минимальный ID контакта. Глобальное объединение однофамильцев/тёзок по ФИО запрещено.
5. Отчёт строится как отдельное дерево для каждой компании: `Руководитель → Компания → Лиды`.
6. В отчёт попадают только рассинхроны между owner руководителя, owner компании и/или owner связанных лидов.
7. В `apply` меняется **только** `ASSIGNED_BY_ID` компании на owner выбранного director contact. Контакты и лиды workflow не изменяет.
8. Если среди лидов компании 3+ разных ответственных, изменение компании блокируется и остаётся на ручную проверку.
9. Если у выбранного director contact нет `ASSIGNED_BY_ID`, автоматического изменения нет.

Файлы результата:

- `company_owner_desync.xlsx` — дерево рассинхрона;
- `company_owner_sync_summary.json` — техническая сводка.

XLSX создаётся с отключённой интерпретацией внешних строк как формул/URL.

Для боевого запуска требуются `mode=apply` и подтверждение `SYNC_COMPANY_OWNERS`.
