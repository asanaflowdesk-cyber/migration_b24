# Опросник инициатив DeskFlow

Ветка «Предложение / Идея» использует анкету из «Опросник_инициативы(1).docx»:
8 вопросов для небольшой инициативы и 14 для крупной, после общих вопросов
о масштабе, требуемом действии, предмете изменения, затронутых участниках
и месте изменения. Начальное меню содержит также «Сообщить о сбое» —
инструкцию обращения в Service Desk, уже использовавшуюся в ветке IT.

## Работа сценария

- ФИО, подразделение, рабочий контакт и руководитель подставляются через
  `user.get` и `department.get`. Сотрудник подтверждает данные и заполняет
  недостающие сведения. При нескольких разных руководителях бот просит
  указать руководителя; пользовательские исправления сохраняются, пока
  соответствующие данные исходного профиля не изменились.
- «Пока не знаю» запускает короткую анкету и отмечает масштаб для уточнения.
- Участников можно выбрать несколько; для «Другое» запрашивается текст.
- Условия и риски раскрываются только после «Есть», срок — после «Есть срок».
  Неизвестные владельцы, требования, ресурсы и риски попадают в список
  сведений для уточнения. Бот не назначает владельца результата за автора.
- «Исправить ответ» открывает выбор конкретного поля. Смена масштаба
  сохраняет ответы, вложения и общие данные; запрашиваются только
  недостающие ответы. Дополнительные ответы другой анкеты остаются
  в описании и отдельных полях задачи.
- Материалы запрашиваются последними. Можно отправить файлы, комментарий,
  ссылки и номера связанных обращений. Замена файлов производится после
  получения непустого нового пакета.
- «Сохранить черновик» сохраняет одну отдельную инициативу сотрудника
  в постоянной SQLite-базе worker. После выхода в главное меню черновик
  доступен через «Предложение / Идея». После перезапуска и открытия нового
  служебного чата черновик привязывается к текущему чату. Новая инициатива
  не удаляет прежний сохранённый черновик; новое сохранение заменяет его.
- «Отправить» создаёт обычную задачу DeskFlow в настроенной группе,
  с существующими правилами назначения ответственного и XML_ID для
  защиты от повторного создания. Сообщение после отправки: «Инициатива
  отправлена на первичное рассмотрение», с номером и ссылкой.

## Поля задачи и доступ

`UF_FLOWDESK_INIT_*` хранят масштаб, действие, предмет, участников, место
изменения, отдельные ответы анкеты, данные инициатора и сведения для
уточнения. Регистрация этих полей использует тот же механизм, что и
существующие `UF_FLOWDESK_*`: при отсутствии административных прав
описание задачи всё равно содержит полную анкету, но недоступные отдельные
поля не записываются. Для получения профиля нужны права вебхука на чтение
сотрудников и структуры компании. Если чтение недоступно, данные вводятся
в анкете вручную.

Руководитель берётся из `UF_HEAD` подразделения; для руководителя самого
подразделения проверяется родительское. Автоматизация стадий, SLA,
эскалаций, передачи в бэклог или реализации остаётся настройкой раздела
задач Б24. Этот сценарий оформляет и отправляет инициативу.

## Обновление и запуск

1. Перенесите изменения из архива в репозиторий, включая новые файлы
   `initiatives.py`, `initiator_profile.py` и `test_initiatives.py`.
2. Запустите workflow **41 | FlowDesk ChatBot Test**. Он включает новый
   сценарий в проверку синтаксиса и запускает весь набор тестов бота.
3. Запустите **42 | FlowDesk Chatbot control** с действием **restart**.
   Постоянная база и сохранённые черновики находятся вне рабочей копии
   GitHub Actions и сохраняются при обновлении.
4. Проверьте в Б24 небольшую инициативу, крупную инициативу, исправление
   масштаба, файлы и сохранение/восстановление черновика. После отправки
   проверьте созданную задачу, её группу, ответственного и отдельные поля.

В архиве добавлены проверки прохождения обеих анкет, условных вопросов,
выбора нескольких вариантов, смены масштаба, исправления ответов, файлов,
миграции старых незавершённых предложений, сохранения и восстановления
черновиков, получения профиля и создания задачи через worker. Локальная
проверка использует тестовые ответы REST; подключение к серверу Б24
при подготовке архива не выполнялось.

Документация REST для получения профиля:

- https://apidocs.bitrix24.com/api-reference/user/user-get.html
- https://apidocs.bitrix24.com/api-reference/departments/department-get.html
