# 36 — Обновление компаний из Google Sheets

Поток обновляет существующие карточки компаний Bitrix24 из листа `update_contact` таблицы «ГПО Недра».

## Фактическая структура листа update_contact

Текущие входные колонки:

| Колонка | Назначение |
|---|---|
| `COMPANY_ID` | ID компании в Bitrix24 — основной ключ |
| `ORIGIN_ID` | БИН компании — контрольный ключ |
| `NAME` | Название только для визуальной проверки |
| `PHONE` | Один или несколько телефонов |
| `EMAIL` | Один или несколько email |
| `WEB` | Статус поиска контактов: `Найдено` / `Не найдено`; **это не сайт компании** |

Колонка `WEB` в этом листе намеренно игнорируется при обновлении Bitrix24.

Если позже потребуется загружать сайт компании, используйте отдельную колонку `WEBSITE`, `SITE`, `Сайт`, `WEBSITE_URL` или `SITE_URL`.

Несколько телефонов или email в одной ячейке разделяются `;` или переносом строки.

## Особенность ORIGIN_ID

В текущем Google Sheet `ORIGIN_ID` хранится числом. Поэтому БИН, начинающиеся с нуля, теряют ведущий ноль и визуально становятся 11-значными.

Поток учитывает это: если в `ORIGIN_ID` ровно 11 цифр, перед сверкой автоматически восстанавливается один ведущий ноль.

Остальные длины считаются ошибкой.

## Безопасность

- `dry_run` ничего не меняет в Bitrix24, но записывает в Google Sheets план изменений.
- `apply` требует подтверждение `APPLY_COMPANY_UPDATES`.
- Пустая ячейка, `—`, `-`, `нет`, `не найдено` ничего не очищает.
- Телефоны, email и сайты только **добавляются**, если такого значения в карточке ещё нет.
- Существующие значения не удаляются и не заменяются.
- Если указан `COMPANY_ID` и БИН/`ORIGIN_ID`, БИН сверяется с `ORIGIN_ID` компании и `RQ_INN` её реквизитов.
- Если `COMPANY_ID` отсутствует, поиск по БИН допускается только при одном однозначном совпадении.
- Повтор одной компании в одном запуске блокируется.
- После `apply` компания перечитывается из Bitrix24 и добавленные значения проверяются.
- `NAME` не меняет название компании.
- `ADDRESS/Адрес` не меняется: адрес и банковские данные в Bitrix24 относятся к реквизитам.

## Добавление мультиполей

Для добавления новых `PHONE`, `EMAIL` и сайта используется `crm.item.update`.

Новые значения отправляются в `fm` с ключами `n0`, `n1`, ... — это формат добавления новых мультиполей в Bitrix24. Уже существующие записи мультиполей не передаются и поэтому не изменяются.

Тип значения по умолчанию — `WORK`. При необходимости можно добавить колонки `PHONE_TYPE`, `EMAIL_TYPE`, `WEB_TYPE`.

## Пользовательские поля

Простые пользовательские поля компании можно обновлять отдельными колонками с точным кодом `UF_CRM_...`.

Пустые значения не передаются. Множественные и файловые пользовательские поля поток намеренно не меняет.

## Что поток пишет обратно в Google Sheets

Если колонок нет, они создаются автоматически справа от текущей таблицы:

- `STATUS` — `DRY_RUN`, `UPDATED`, `SKIP` или `ERROR`;
- `CHANGES` — конкретный список изменений;
- `MESSAGE` — результат или причина ошибки;
- `BITRIX_COMPANY_ID` — найденный ID карточки;
- `UPDATED_AT` — время запуска в UTC.

Для текущего листа A:F результат появится в G:K.

## Запуск

GitHub Actions → `36 | Компании — обновление данных из Google Sheets` → `Run workflow`.

По умолчанию уже подставлены:

- таблица: `1WuRHHyQm5lHxDlW81m4P0oZJ6X_SDYj1bN-NOx8aM2k`;
- лист: `update_contact`;
- режим: `dry_run`.

Первый запуск всегда делайте в `dry_run`.

После проверки результата запускайте `apply` и в поле `confirm` вводите:

`APPLY_COMPANY_UPDATES`

Используются существующие secrets:

- `TARGET_BITRIX_WEBHOOK_URL`;
- `GOOGLE_SERVICE_ACCOUNT_JSON`.
