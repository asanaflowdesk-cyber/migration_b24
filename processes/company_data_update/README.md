# 36 — Обновление компаний из Google Sheets

Поток обновляет существующие карточки компаний Bitrix24 из Google Sheets. Основной сценарий — массово добавить найденные телефоны, email и сайты без ручного открытия каждой карточки.

## Безопасность

- \`dry_run\` ничего не меняет в Bitrix24, но пишет в Google Sheets план изменений.
- \`apply\` требует подтверждение \`APPLY_COMPANY_UPDATES\`.
- Пустая ячейка ничего не очищает.
- Телефоны, email и сайты только **добавляются**, если такого значения в карточке ещё нет. Существующие значения не удаляются и не заменяются.
- Если указан \`COMPANY_ID\` и БИН/\`ORIGIN_ID\`, БИН дополнительно сверяется с \`ORIGIN_ID\` компании и \`RQ_INN\` её реквизитов.
- Если \`COMPANY_ID\` не указан, поиск по БИН допускается только когда найден ровно один объект.
- Повтор одной компании в одном запуске блокируется, чтобы две строки не перетёрли друг друга.
- После \`apply\` карточка перечитывается из Bitrix24, и запись считается успешной только после проверки результата.

## Таблица

Минимум нужен \`COMPANY_ID\` или \`ORIGIN_ID/БИН\`.

Рекомендуемый формат:

| COMPANY_ID | ORIGIN_ID | NAME | PHONE | EMAIL | WEB |
|---|---|---|---|---|---|
| 96 | 250740900736 | ТОО Компания | +7 700 000 00 00 | info@example.kz | https://example.kz |

Поддерживаются русские заголовки \`БИН\`, \`Название\`, \`Телефон\`, \`Почта\`, \`Сайт\`.

Несколько значений в одной ячейке разделяйте \`;\` или переносом строки.

Тип мультиполя по умолчанию — \`WORK\`. При необходимости можно добавить \`PHONE_TYPE\`, \`EMAIL_TYPE\`, \`WEB_TYPE\`.

Пользовательские поля компании можно обновлять отдельными колонками с точным кодом \`UF_CRM_...\`. Пустые значения не передаются. Множественные и файловые пользовательские поля поток намеренно не меняет.

\`NAME/Название\` используется только для контроля и не переименовывает компанию.

\`ADDRESS/Адрес\` намеренно не изменяется: адрес и банковские реквизиты в Bitrix24 нужно менять через методы реквизитов, а не обычное обновление компании.

## Что поток пишет обратно в Google Sheets

Если колонок нет, они создаются автоматически:

- \`STATUS\` — \`DRY_RUN\`, \`UPDATED\`, \`SKIP\` или \`ERROR\`;
- \`CHANGES\` — конкретный список изменений;
- \`MESSAGE\` — результат или причина ошибки;
- \`BITRIX_COMPANY_ID\` — найденный ID карточки;
- \`UPDATED_AT\` — время запуска в UTC.

## Запуск

GitHub Actions → \`36 | Компании — обновление данных из Google Sheets\` → \`Run workflow\`.

Параметры:

- \`spreadsheet\` — ID таблицы или полная ссылка на Google Sheets;
- \`sheet\` — имя листа, по умолчанию \`company_update\`;
- \`mode\` — сначала \`dry_run\`, затем \`apply\`;
- \`confirm\` — для \`apply\` ввести \`APPLY_COMPANY_UPDATES\`.

Используются существующие secrets репозитория:

- \`TARGET_BITRIX_WEBHOOK_URL\`;
- \`GOOGLE_SERVICE_ACCOUNT_JSON\`.

Google-таблица должна быть доступна сервисному аккаунту из \`GOOGLE_SERVICE_ACCOUNT_JSON\`.

## Артефакт запуска

В \`36-company-data-update-*\` сохраняются:
