# Исправления и оставшиеся входные блокеры

Дата ревизии: 2026-09-10.

## Исправлено

- Команды `import` и `verify` завершаются ненулевым кодом при ошибках или неполной сверке.
- Перед первой записью проверяются checksum и число строк всех 53 наборов дампа, обязательные live-наборы и межсущностные ссылки.
- Resume-карта привязана к checksum дампа, конфигурации, карты пользователей и целевому порталу; повреждённое или чужое состояние отклоняется.
- Сетевые сбои после изменяющих REST-вызовов больше не вызывают слепой повтор, способный создать дубль.
- Автоматическое слияние компаний и контактов ограничено точным миграционным маркером.
- Обновление связей контакт—компания и лид/сделка—контакт сохраняет уже существующие ручные связи коробки.
- Неоднозначное сопоставление пользователей и отсутствующие обязательные CRM-связи блокируют объект вместо назначения случайному пользователю или компании.
- Отчёты по умолчанию скрывают персональные payload; webhook-токены удаляются из сообщений, CSV/XLSX защищены от formula injection.
- FlowDesk проверяет ответственного заранее и использует стабильный `XML_ID`, поэтому повтор одного события не приглашает пользователя и не создаёт вторую задачу.
- Восстановление лидов получает workflow-параметры через проверяемое окружение, без подстановки пользовательского текста в командную строку.
- Синхронизация ответственных не считает одинаковое ФИО в разных компаниях доказательством личности.
- XML из XLSX разбирается через `defusedxml`; зависимости зафиксированы точными версиями.
- GitHub Actions закреплены по полным commit SHA, Artifact хранятся 7 дней, добавлен общий CI.
