Репозиторий содержит только действующие процессы коробочного Bitrix24. Разовый блок переноса CRM из облака удалён: workflows `01`, `10–13`, `processes/cloud_export` и `processes/cloud_to_box` больше не используются и в репозитории отсутствуют.

## Workflow 33 — перенос пакетов исключённых пользователей

Назначение: убрать остатки лидов с исключённых пользователей и привести связанный пакет к одному ответственному. Стадии лидов этот workflow **не меняет**.

Базовый список исключённых пользователей:

```text
15,17,19,22,23,39,44
```

Автоматические РОП для ещё не распределённых пакетов:

```text
72,73
```

Правила пакета:

1. Если определён учредитель — пакет объединяется по ФИО учредителя и связанным компаниям.
2. Если учредителя нет, но есть компания — `компания + её лиды` остаются полноценным сокращённым пакетом.
3. Если нет и компании — отдельный лид считается минимальным пакетом.
4. Лиды действующих пользователей не забираются. Они используются только как контекст для определения уже существующего владельца пакета.
5. Если пакет уже закреплён за одним действующим пользователем, остатки исключённых пользователей переводятся к этому же владельцу. Пакет заново между `72/73` не балансируется.
6. Если пакет уже частично перенесён на `72` или `73`, перенос продолжается на того же РОПа.
7. Если пакет не имеет действующего владельца, он целиком назначается на `72` или `73`; балансировка идёт по количеству лидов без дробления пакета.
8. Любой пакет, связанный с Талдыкорганом через подразделение текущих исходных ответственных, пропускается целиком.
9. Лид `401` защищён: пакет с ним не меняется автоматически.
10. Меняется только `ASSIGNED_BY_ID`. `STATUS_ID` и другие поля workflow 33 не трогает.

`dry_run` формирует один файл:

```text
excluded_user_reassignment.csv
```

`apply` выполняет тот же рассчитанный план, показывает прогресс `X/Y`, затем перечитывает CRM. Если после первой проверки остаются расхождения, workflow один раз повторяет только их внутри того же запуска и снова проверяет. Отдельного repair-workflow и отдельных plan/summary-файлов нет.

Для `apply` требуется подтверждение:

```text
REASSIGN_EXCLUDED_USERS
```
