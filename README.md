# Выгрузка Bitrix24 в JSON и Excel для переноса

Скрипт создаёт максимально полную логическую выгрузку данных облачного Bitrix24 через REST API. Он рассчитан на инвентаризацию и перенос небольшого портала: сделки, лиды, контакты, компании, ответственные, воронки, стадии, проекты и задачи.

Результат состоит из:

- исходных ответов REST API в `json/raw_api/`;
- отдельных JSON-файлов по сущностям в `json/datasets/`;
- единого Excel `bitrix24_export.xlsx` для проверки и сопоставления;
- `manifest.json` с количеством строк и контрольными суммами;
- ZIP-архива всего дампа.

JSON является основным источником для последующего импорта. Excel нужен для просмотра, фильтрации и подготовки таблицы соответствий старых и новых ID.

## Что выгружается

### CRM

- лиды со всеми доступными системными и пользовательскими полями;
- сделки со всеми доступными системными и пользовательскими полями;
- контакты и компании;
- телефоны, email, сайты и мессенджеры;
- основные и дополнительные связи сделка–контакт;
- связи лид–контакт и контакт–компания;
- товарные позиции лидов и сделок;
- CRM-дела: звонки, встречи, письма и другие активности;
- комментарии таймлайна;
- реквизиты, адреса, банковские реквизиты и шаблоны реквизитов;
- смарт-процессы, их поля, элементы и воронки, если доступны;
- справочники полей, статусов, источников, стадий и воронок.

### Пользователи и работа

- пользователи и закреплённые менеджеры;
- подразделения;
- рабочие группы, проекты, Scrum и коллабы;
- задачи со всеми доступными полями и участниками;
- стадии канбана задач по проектам и группам.

В таблицах сохраняются исходные технические ID. В сделках дополнительно выводятся название воронки, название стадии и ФИО ответственного. В лидах выводятся название статуса и ответственный. Дополнительные контакты сделки находятся в отдельной таблице `Deal_Contacts`.

## Ограничение

Это не физический дамп базы облачного Bitrix24. REST API возвращает только данные, доступные пользователю входящего webhook, и только те разделы, для которых в облаке существует метод чтения.

Если какой-либо метод недоступен, скрипт записывает ошибку в `Errors` и продолжает выгрузку остальных разделов. Для переноса примерно 1000 карточек этого формата достаточно: исходные карточки, поля, связи и справочники ID сохраняются.

ID пользователей, стадий, воронок и карточек в новом портале будут другими. При импорте потребуется создать таблицы соответствий `старый ID → новый ID`.

## Настройка webhook

Создайте входящий webhook от администратора портала. Ему нужны права чтения минимум для:

- CRM;
- задач;
- пользователей;
- структуры компании;
- рабочих групп и проектов.

Webhook является секретом. Не вставляйте его непосредственно в код и не публикуйте репозиторий с заполненным `.env`.

## Запуск через GitHub Actions

1. Создайте приватный репозиторий GitHub.
2. Загрузите в него содержимое этой папки.
3. Откройте `Settings → Secrets and variables → Actions`.
4. Создайте secret `BITRIX_WEBHOOK_URL`.
5. Вставьте полный URL webhook, например:

   `https://yourportal.bitrix24.kz/rest/1/xxxxxxxxxxxxxxxx/`

6. Откройте `Actions → Export Bitrix24 to JSON and Excel → Run workflow`.
7. Скачайте artifact `bitrix24-dump`.

## Запуск в GitHub Codespaces

```bash
cp .env.example .env
pip install -r requirements.txt
python bitrix_export.py
```

Результат появится в каталоге `output/`.

## Локальный запуск

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
python bitrix_export.py
```

Linux/macOS:

```bash
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python bitrix_export.py
```

## Параметры командной строки

```bash
python bitrix_export.py --help
```

Отключить необязательные тяжёлые разделы:

```bash
python bitrix_export.py --no-timeline
python bitrix_export.py --no-activities
python bitrix_export.py --no-smart-processes
python bitrix_export.py --no-task-stages
```

Задать собственный каталог:

```bash
python bitrix_export.py --output output/current_portal
```

## Что проверять перед импортом

В первую очередь:

- `Deals` — `CATEGORY_ID`, `CATEGORY_NAME`, `STAGE_ID`, `STAGE_NAME`, `ASSIGNED_BY_ID`;
- `Leads` — `STATUS_ID`, `STATUS_NAME`, `ASSIGNED_BY_ID`;
- `Deal_Contacts` — все дополнительные контакты сделок;
- `Contacts` и `Companies` — карточки клиентов;
- `Users` — соответствие ID менеджеров и ФИО;
- `Deal_Categories` и `CRM_Statuses` — структура воронок и стадий;
- `Deal_Fields`, `Lead_Fields`, `Contact_Fields`, `Company_Fields` — пользовательские поля.

Исходный портал после выгрузки не изменяется: скрипт выполняет только методы чтения.
