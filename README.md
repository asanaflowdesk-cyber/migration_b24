# Bitrix24: выгрузка облака, перенос в коробку и регистрация пользователей

В одном репозитории находятся три независимых процесса. Они разделены по папкам, чтобы выгрузка облака, разовый перенос CRM и регулярная регистрация пользователей не смешивались.

## Структура

```text
.github/workflows/                 GitHub Actions; GitHub требует хранить их именно здесь
common/                            общий REST-клиент коробочного Bitrix24
scripts/                           техническая подготовка Python на рабочем компьютере
processes/
  cloud_export/                    выгрузка текущего облачного Bitrix24
  cloud_to_box/                    перенос выгруженных данных в коробку
  user_registration/              отдельная регистрация пользователей из Excel
```

## Потоки в разделе Actions

### 01 | Облако — выгрузить данные

Запускается на сервере GitHub и выгружает данные облачного Bitrix24 в JSON и Excel. Использует секрет `BITRIX_WEBHOOK_URL`. Результат скачивается из Artifacts.

Главный файл процесса: `processes/cloud_export/export_bitrix.py`.

### 10–13 | Миграция облако → коробка

Работают через Windows self-hosted runner внутри корпоративной сети и используют секрет `TARGET_BITRIX_WEBHOOK_URL`.

Порядок запуска:

1. `10 | Миграция — проверить план`.
2. `11 | Миграция — подготовить пользователей облака`.
3. `12 | Миграция — импортировать CRM в коробку` сначала в `dry_run`, затем в `apply`.
4. `13 | Миграция — сверить результат`.

Входной Excel текущего облака находится здесь:

```text
processes/cloud_to_box/input/bitrix24_export.xlsx
```

Когда создается новая выгрузка облака, заменить нужно только этот файл.

Конфигурация миграции и сопоставление пользователей находятся здесь:

```text
processes/cloud_to_box/config/
```

### 20 | Пользователи — регистрация из Excel

Это отдельный постоянный процесс, не зависящий от миграции. В Excel указываются ФИО, email и подразделение:

```text
processes/user_registration/input/users_to_invite.xlsx
```

Сначала запускать `dry_run`. Для реального приглашения выбрать `apply` и ввести `REGISTER_USERS`.

## Секреты репозитория

В `Settings → Secrets and variables → Actions` должны быть:

- `BITRIX_WEBHOOK_URL` — webhook облачного Bitrix24 только для выгрузки;
- `TARGET_BITRIX_WEBHOOK_URL` — webhook коробочного Bitrix24 для миграции и регистрации пользователей.

Webhook нельзя записывать в код, Excel, логи или `.env`, который отправляется в GitHub.

## Важное ограничение GitHub

Папки самих процессов разделены. Файлы workflow нельзя разложить по подпапкам: GitHub распознает только файлы, лежащие непосредственно в `.github/workflows`. Поэтому они сгруппированы номерами `01`, `10–13` и `20`.
