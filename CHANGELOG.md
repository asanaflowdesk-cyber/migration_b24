## 2026-09-07 — Новые e-Qazyna лиды всегда стартуют в «Новый»

- Полностью убрано наследование стадии от предыдущего связанного лида.
- Любая новая заявка принудительно создаётся в `NEW`; внешняя настройка `BITRIX_LEAD_STATUS_ID` больше не может отправить новый лид в другую стадию.
- Единственное исключение — последний связанный неудачный лид с причиной `Уже работает с Евразией`: новая заявка создаётся в `JUNK`.
- Для enum-поля причины распознаются текст, ID и список; при создании нового лида записывается целевой ID значения Bitrix24, а не текстовая подпись.
- Повтор той же e-Qazyna заявки по номеру по-прежнему пропускается и не сбрасывает уже существующий лид в `NEW`.

## 2026-08-27 — Дерево рассинхрона по руководителю

- Workflow `31` перестроен вокруг руководителя как источника истины: `Руководитель → Компания → Лиды`.
- Один руководитель с несколькими компаниями объединяется по ФИО в одно дерево.
- Отчет показывает шесть человекочитаемых колонок и подсвечивает ответственных, отличающихся от ответственного руководителя.
- `apply` меняет только компании; случаи с 3+ разными ответственными по лидам остаются ручными.
- Для будущих e-Qazyna заявок добавлен поиск исторического ответственного того же руководителя по другим компаниям.

## 2026-08-27 — Ответственный компании по первому лиду

- e-Qazyna parser больше не меняет `ASSIGNED_BY_ID` уже существующей компании.
- Добавлен workflow `31 | Компании — ответственный по первому лиду`.
- Сверка использует самый ранний связанный лид по `DATE_CREATE`, затем по `ID`.
- Добавлен отдельный отчет по компаниям с 3+ разными ответственными среди связанных лидов.
- В `apply` изменяется только `ASSIGNED_BY_ID` компании; лиды, контакты и сделки не изменяются.
