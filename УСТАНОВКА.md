# Установка DeskFlow внутри компании

ИТ устанавливает код бота и две страницы в коробке. Владелец после этого управляет сценарием из личного диалога. В архиве лежит полный код для отдельной установки.

## Что подготовить

- Тестовый коробочный Б24 с методами `imbot.v2`, PHP с cURL и Python 3.10 или новее на сервере обработчика.
- ID владельца из его профиля Б24. Для теста отдельный бот и отдельная база состояния.
- Входящий вебхук с правами на регистрацию и работу бота, чтение сотрудников и подразделений, чтение метаданных Диска и создание задач. Проверьте права на целевой проект и постановку задач от лица сотрудников. Поля DeskFlow при первом запуске создаются через API, если вебхуку разрешено управлять пользовательскими полями задач. При ограниченных правах поля подготавливает администратор Б24.
- Постоянный закрытый каталог для двух баз SQLite. У сервиса должна быть запись в этот каталог. Резервные копии журнала и секретов хранятся с теми же ограничениями доступа.

## Куда разместить файлы

| Компонент | Путь |
| --- | --- |
| Страница редактора | `/local/tools/deskflow-admin/index.php` в корне Б24 |
| Переходы по ссылкам и файлам | `/local/tools/deskflow-action/index.php` в корне Б24 |
| Закрытые настройки PHP | `/etc/deskflow-admin.php` и `/etc/deskflow-bridge.php` |
| Код бота | Например, `/opt/deskflow` на внутреннем сервере |
| Состояние бота и журнал | `flowdesk_state.sqlite3` в постоянном каталоге сервиса |
| Версии и права редактора | `deskflow_editor.sqlite3` рядом с базой состояния |

Если Б24 и бот размещены на одной машине, PHP обращается к `127.0.0.1:8765`. Для двух серверов настройте внутренний HTTPS-прокси к этому адресу на сервере бота и разрешите доступ к прокси с сервера Б24. Укажите внутренний адрес в конфигурации PHP. Синхронизируйте время на обоих серверах.

## Первая установка

1. Распакуйте ZIP. Из папки `DeskFlow` подготовьте файлы, подставив числовой ID владельца.

   ```sh
   python3 tools/prepare_portal.py --owner-id 123 --stage ./install-local
   ```

   При двух серверах добавьте `--upstream https://deskflow.internal.example`. При использовании внутреннего центра сертификации добавьте `--ca-file /путь/к/сертификату.pem`. Скрипт создаёт файлы в указанной новой папке и записывает общий случайный ключ в обе конфигурации.
2. Из `install-local/webroot/local/tools` перенесите папки `deskflow-admin` и `deskflow-action` в `/local/tools` в корне Б24. Из `install-local/private` перенесите два PHP-файла в `/etc`, вне каталога сайта. Дайте PHP-процессу чтение этих файлов. Для другого пути к конфигурации задайте в окружении PHP `FLOWDESK_ADMIN_PORTAL_CONFIG`. Файл `deskflow-bridge.php` хранится рядом с конфигурацией.
3. Скопируйте распакованный код на сервер бота. Подготовьте окружение.

   ```sh
   python3 -m venv .venv
   .venv/bin/python -m pip install -r processes/flowdesk/requirements.txt
   ```

4. Перенесите `install-local/private/worker.env` в закрытый каталог и заполните `TARGET_BITRIX_WEBHOOK_URL` конечным HTTPS-адресом входящего вебхука. Укажите постоянный путь в `FLOWDESK_CHATBOT_DB`. Для тестового бота задайте отличающийся `FLOWDESK_BOT_CODE` и при необходимости `FLOWDESK_BOT_NAME`. Для запуска используется `python -u -m processes.flowdesk_chatbot.bitrix_worker` с этим окружением. Пример Linux-службы лежит в `deploy/deskflow.service`. Настройте фактические пути и служебного пользователя, затем подключите файл окружения в `EnvironmentFile`.
5. Проверьте PHP перед включением страниц.

   ```sh
   php -l portal/admin/index.php
   php -l portal/action/index.php
   php -l portal/deskflow-bridge.php
   ```

6. Запустите один тестовый процесс. Войдите под владельцем, отправьте `SOS` в личном диалоге, откройте «Управление DeskFlow» и проверьте тестовый сценарий. Первое нажатие «Сохранить и применить» включает конструктор для новых обращений. Проверки на портале перечислены в [ПРОВЕРКА.md](ПРОВЕРКА.md).

При сохранении существующего Windows-запуска используйте ту же служебную учётную запись. `python -m processes.flowdesk_chatbot.worker_control start` использует папку `.flowdesk-chatbot` в её профиле и копирует код в каталог запуска. Ключ и вебхук передаются через закрытое окружение службы.

## Обновление существующего DeskFlow

1. Остановите старый процесс. Сохраните согласованную копию кода, параметров запуска, файлов состояния и закрытых PHP-настроек. Если рядом с SQLite остались `-wal` и `-shm`, сохраните их вместе с базой.
2. Установите новый код и PHP-страницы. Для действующего бота сохраните вебхук, код, имя команды, токен и прежний путь к базе. При обновлении установленного редактора используйте его ключ и ID владельца. В SQLite добавятся таблицы журнала и версий, текущие диалоги и прежние черновики сохранятся.
3. Запустите один процесс с этой базой. Проверьте старый чат и возобновление старого черновика. Затем примените проверенный сценарий. Настройка сценария в дальнейшем выполняется в Б24.

## Как откатить

- **Изменился сценарий.** На вкладке «Версии» выберите прежнюю версию и нажмите «Восстановить и применить». Новые обращения пойдут по ней.
- **Нужно вернуть прежний код.** Остановите сервис и отдельно сохраните текущее состояние. Верните прежний код и конфигурацию. При необходимости восстановления снимка SQLite предварительно сверяйте задачи, созданные после снимка, по идентификаторам обращений. Иначе старое состояние может потерять сведения об уже проведённой отправке. Если за время обновления появились новые черновики, оставьте актуальные базы в резервной копии.
- **Б24 не ответил при создании задачи.** Сверьте обращение по `XML_ID` вида `FLOWDESK_CHAT_<ID обращения>`. После неопределённого результата бот ищет задачу, а оператор видит подтверждённые ответы в журнале. Перед ручной повторной передачей нужно выяснить итог первого запроса.
